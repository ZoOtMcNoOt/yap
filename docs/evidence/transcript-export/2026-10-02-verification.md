# Original transcript export

**Owner:** Grant McNatt. **Date:** 2026-10-02. **Scope:** Development working tree; Linux native IO and Chromium fixture workflows.

Transcript review now offers **Export text** for its selected original transcript. The renderer passes only the owned source path. Native code validates the committed live or published remote source, opens a destination picker, revalidates after selection, and publishes UTF-8 text atomically to a new `.txt` file. Missing extension receives `.txt`; other formats are rejected. Existing files, directories, symlinks and Yap's internal data directory are preserved. Cancellation returns a distinct receipt. Local export does not require a ready server.

The action toolbar wraps; busy export prevents duplicate submission while retaining keyboard focus. Failure remains beside the selected transcript and supports an explicit retry. Export does not modify source text, accepted corrections, or history selection. Corrected revisions, timed text and speaker formats are outside this contract.

## Qualification boundary

Chromium replaces the native command response; it does not open a native picker or certify a native-window round trip. Native tests exercise real validated source reads and filesystem publication independently. The registered command compiles in the Linux native suite. Windows must still exercise the actual save picker: choose a new file, cancel, select an existing file, select an unwritable folder, close the picker, and verify keyboard focus and original/export bytes. Windows/NTFS no-replace behavior, picker focus and platform permission errors are not qualified by Linux tests.

Export is byte- and concurrency-bounded. Destination filesystem operations may wait for the filesystem; they are not abandoned on a timer that could let a file appear after a reported failure. There is no new inference, enterprise identity, installer, or production qualification claim.
